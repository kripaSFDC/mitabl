Frequently Asked Questions

Everything you need to know about discovering and enjoying local food with mitabl.

Platform Basics

What is mitabl?
mitabl is a home-cooked food marketplace platform connecting Foodies (customers) and Cooks operating virtual kitchens (miKitchens).

Is this website transactional?
No. The public website is an informational and marketing surface. Transactional flows (authentication, ordering, payments, support ticket API actions, and account operations) run through the mobile app and backend API.

How is traffic split across the platform?
Ingress policy routes public pages on / to the marketing website, /api/* to the backend API, and /admin to the operations admin service.

App Experience

What can Foodies do in the mobile app?
Foodies can discover kitchens, browse menus, place orders, manage cards/payments, and submit reviews.

Can one app support both personas?
Yes. The Flutter mobile app contains both Foodie and Cook journeys in a single application.

Cook Operations

What can Cooks manage?
Cook-side API routes support certificate checks, miKitchen profile updates, menu item create/edit/delete, incoming order handling, dashboard data, and fulfillment status updates.

Are cook actions role-restricted?
Yes. Cook operations are behind authenticated /api/v1 routes with restaurant middleware.

Ordering & Payments

How are customer orders handled?
Customer routes include restaurant discovery/filtering, order creation, order history/details, booked date/time checks, and order cancellation with reason.

Which payment flows are implemented?
The backend exposes card management, payment intent/confirm flows, checkout session creation, and payment execution endpoints.

Support & Ticketing

How does support ticketing work?
Backend public routes provide support ticket create, read, and reply endpoints with dedicated throttle middleware.

Does the website proxy support requests?
No. The stateless cutover removed website support-ticket proxy routes; ticket APIs are owned by the backend.

Security & Privacy

What security controls are enforced at ingress?
TLS is terminated at nginx with HSTS and security headers, and admin traffic has additional network controls and cache restrictions.

Where is persistence managed?
Backend is the persistence authority for platform entities. The website is static and does not require a runtime database to render pages.

Admin & Access Boundaries

How is admin access separated?
The admin panel is served on /admin and restricted to trusted network ranges at ingress.

Can admin identities use API mobile routes?
No. The API activity middleware denies role_id 1 identities on the API guard and instructs them to authenticate via the web admin panel.
